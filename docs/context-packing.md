# 上下文打包：只按最近轮数 / Context packing by recent turns

在设置页「上下文打包控制（仅按最近轮数）」中操作：开关默认关闭，保留轮数 `1–20`（默认 `3`）；点击开关直接保存，修改轮数需保存轮数。不会对整个请求设置 Token 数量硬上限。

在模型请求组装前，插件使用 DSH Session surface 的 `replace`，把部分已完成的较早轮次从**模型可见面**中替换为短标记；原始追加式事件日志仍保留。替换消息在 v0.3.6 起显式包含新的 UUID `data.id`，以满足 DSH V4 重放验证。

裁剪遵守以下约束：当前轮、受保护的 system/developer 节点、当前可见而无法安全配对的工具消息、宿主版本不支持的消息，不做冒险删除。确认已被最新有效快照替代的旧系统提示词，可在 DSH `in-history` 机制证据充分时清理。无法安全裁剪就跳过相关片段并**允许会话继续**。

### 结果如何理解

- `maxHistoryTurns` 是对**可安全处理的历史会话轮次**的限制目标，而不是系统消息数量的上限。
- 模型请求仍可能包含系统指令、工具 schema、运行时上下文、任务指令、模型提供的缓存上下文等。
- 节省旧历史字符不等于同比例减少输入 Token 和费用；提示词缓存率可能升降。
- 关闭开关阻止**未来的新裁剪操作**，不会自动撤销已经写入的 surface 替换事件。
- **旧版警告：** v0.3.5 写入的占位事件可能缺少 UUID。升级到 0.3.6 只防止新事件损坏，旧会话须另行修复。见 [身份修复](session-identity-fix.md)。

默认配置片段：

```json
{"contextPacking":{"enabled":false,"maxHistoryTurns":3}}
```
