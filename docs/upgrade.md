# 升级、回滚及旧会话恢复 / Upgrade, rollback and legacy-session recovery

## 0.3.5 → 0.3.6

1. 在设置页**关闭「上下文打包控制」**。注意插件总开关与上下文打包开关是不同设置。
2. 完整备份现有插件、插件配置/状态目录，以及可能受影响的 DSH 会话目录；记录备份文件的 SHA256。
3. 从经过核对的 v0.3.6 源码安装包，通过 DSH 插件管理器升级当前 bundle `dsh-optimizer`；**不要并行安装第二份**。
4. 按提示重启，检查显示版本、加载日志、配置持久化、台账和检查点。
5. 在新测试会话里验证 6–8 轮以上对话及工具调用；先开打包、再重启，确认旧会话可重载。之后再决定是否在日常会话开启。

## 若 0.3.5 已写入坏事件

**升级插件不会更改旧会话中的 `.jsonl.zstd` 文件**。如果宿主提示 `session event at seq … lacks an identified message`：

- 停止在故障会话中继续操作，并关闭打包开关。
- 完整备份会话目录和插件数据。仅以原件副本做诊断。
- 使用与当前 DSH 版本匹配的 Session V4 读取器重放候选；不得只以 JSON 解析成功判定可恢复。
- 仅对确认为旧 `dsh-optimizer-context-packing` 标记且缺少 `data.id` 的事件生成独立 UUID；保留 seq、sourceEventSeqs、surfaceOp 和其他事件完全不变。
- 先生成**独立候选文件**并验收，再在 DSH 进程完全退出后谨慎替换。失败时恢复备份；禁止直接批量改写未确认的会话。
- 这是事故修复建议，**不是插件自带的自动修复功能**；不同事件来源可能存在其他结构性问题。

详情见 [故障说明](session-identity-fix.md)。不应将任何真实会话文件上传公开 GitHub Issue。

## 回滚/卸载

通过 DSH 插件管理器恢复到经过验证的版本或移除 bundle，避免自行重写 profile 依赖。运行数据与源码目录相互独立；卸载可能保留 `<DSH_HOME>/storages/dsh-optimizer` 中的配置、台账和检查点。要删除数据时先退出 DSH 并备份，只操作插件本身目录，不删除宿主会话日志。

**警告：** 如果回退到 v0.3.5，务必保持上下文打包关闭，否则可能重新写入匿名替换标记。建议不要回退到有已知数据损坏缺陷的版本。
