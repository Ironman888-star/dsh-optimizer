# 常见问题 / FAQ

### 开了最近 2 轮，为什么请求仍很大？

打包仅操作安全可裁的旧会话历史。系统和开发者指令、工具 schema、运行时注入及新一轮的大型工具结果可能仍占大头；字符下降不等于费用下降。请比较实际输入 Token、缓存 Token、同类任务的计费。

### 关闭后，旧聊天日志会恢复到模型可见面吗？

不会自动撤销已写入的 Session surface 替换。原始追加式日志通常仍在，但模型当前可见面和原始历史展示是不同的概念。关闭只影响后续自动打包。

### 为什么打开旧会话会出现 `lacks an identified message`？

v0.3.5 已知缺陷可能写入缺少 `data.id` 的裁剪标记。v0.3.6 已防止新的同类事件，但不会自动修复旧事件。不要继续使用有缺陷的 0.3.5 打包，参见 [恢复说明](session-identity-fix.md)。其他插件也可能产生类似异常，应按事件 `source` 分析，不要盲目补字段。

### 插件是否会自动控制全工作区扫描权限？

不会。旧的独立历史/工作区权限审批守卫已于 0.3.5 移除。可编辑任务指令只提供行为建议。

### 默认任务指令编号为什么不是连续的？

公开版预置已规范为 `1–5` 连续编号，对应五条原有指令，语义不变；这与实机验收时的手动编号修正一致。已保存的个人自定义文本存放于本地配置，而不是开源代码。

### 可以直接把 ZIP 上传到 GitHub 当仓库吗？

建议解压后将 `package.json`、源码和 Markdown 文档放在 GitHub **仓库根目录**，再建立 `v0.3.6` tag 和 GitHub Release；仓库里不要上传实际运行数据。详情见 [发布检查清单](release-checklist.md)。
